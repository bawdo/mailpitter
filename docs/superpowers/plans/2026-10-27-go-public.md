# Go Public Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make mailpitter a public project with tag-driven signed releases, the full set of community files, a hardened CI whose integration job really runs, and scripts that apply the repository settings in phases.

**Architecture:** A port of caddy_shack's 2026-10-27 setup. Every script, workflow and document is copied from `/Users/bawdo/working/projects/caddy_shack` (referred to below as `CS/`) and adapted by module path, binary name, repository slug and prose. Each script arrives with its `_test.sh` suite, run by `make test-scripts`. The integration job installs caddy_shack from its v0.1.0 release and mailpitter from source, and a strict environment variable turns the suite's skip guards into failures.

**Tech Stack:** Go 1.26.x in CI (go.mod stays `go 1.25.0`), bash scripts tested with bash, GitHub Actions SHA-pinned, `gh` for API calls, golangci-lint v2, govulncheck, shellcheck v0.11.0, Codecov, OpenSSF Scorecard, CodeQL default setup.

**Spec:** `docs/superpowers/specs/2026-10-27-go-public-design.md`

## Global Constraints

- Commits GPG-signed, past tense, subject 60 characters or fewer, no agent attribution anywhere. Ask before each commit. Never push.
- Australian English. No em dashes or en dashes in any tracked file outside `docs/superpowers/`.
- Module path `github.com/bawdo/mailpitter`, binary `mailpitter`, repository slug `bawdo/mailpitter`. Wherever a caddy_shack file says `caddy_shack` as the project, write `mailpitter`; where it names the dependency caddy_shack (SECURITY.md trust boundary, the integration job), it stays.
- Every GitHub Action pinned to a 40-hex commit SHA with a `# vX.Y.Z` comment. Reuse the SHAs already in `CS/.github/workflows/*.yml`; they resolved upstream today.
- CI Go version `'1.26.x'`. golangci-lint `v2.15.0`. govulncheck `v1.9.0`. shellcheck `v0.11.0` with the SHA256 in `CS/.github/workflows/ci.yml`.
- caddy_shack dependency in CI: `v0.1.0`, archive `caddy_shack_0.1.0_linux_amd64.tar.gz`, verified against `checksums.txt` and `gh attestation verify --repo bawdo/caddy_shack --signer-workflow bawdo/caddy_shack/.github/workflows/release.yml`.
- Codecov floor `80%`, threshold `1%`, enforcing; patch `70%`, informational.
- Topics: `mailpit`, `smtp`, `email`, `docker`, `go`, `golang`, `cli`, `local-development`, `caddy`. Description: `A CLI that runs one shared local Mailpit container, registers its UI with caddy_shack at mailpit.test, and helps consumer projects plug in`.
- Nothing may require a second person: zero required approvals, no code-owner review, no approval for unattributed changes.
- Remotes policy is `local` (no `.claude/wombat-rnd.json`): hand every push and pull request command to the maintainer.

```go
// prerequisite skips the test unless MAILPITTER_INTEGRATION_STRICT is set,
// in which case a missing prerequisite is a failure: CI installs them all,
// so a skip there would hide a broken install step.
func prerequisite(t *testing.T, ok bool, format string, args ...any) {
	t.Helper()
	if ok { return }
	if os.Getenv("MAILPITTER_INTEGRATION_STRICT") != "" {
		t.Fatalf("strict: "+format, args...)
	}
	t.Skipf(format, args...)
}
```
